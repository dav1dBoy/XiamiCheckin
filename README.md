# 虾米爱打卡 · XiamiCheckIn

一个支持工作日及可选周末提醒、按目标 WiFi 判断的 Android 打卡助手。到达设定时间并连接指定 WiFi 后，自动打开飞书，约 5 秒后返回助手；未连接时等待网络，锁屏时提醒并等待解锁。

| 项目 | 信息 |
| --- | --- |
| App 名称 | 虾米爱打卡 |
| 工程 / 建议仓库名 | `XiamiCheckIn` |
| Android 包名 | `com.xiami.checkin` |
| 版本 | `1.0.0` |
| 支持系统 | Android 8.0（API 26）及以上 |

## 功能

- 添加、删除多个提醒时间，默认仅周一至周五执行。主界面可开启「周末也自动打开」，周六、周日也使用同一组时间，开关状态自动保存。
- 使用系统 `AlarmManager` 的 `RTC_WAKEUP` 单次闹钟，获得「闹钟和提醒」权限后通过 `setExactAndAllowWhileIdle` 调度，不依赖助手页面或进程持续运行。同一时间点每天最多触发一次。
- 每次收到闹钟先安排下一次；开机、应用更新、修改时间/时区、调整周末开关和授予闹钟权限后重新安排。未授权精确闹钟时降级为可能延迟的系统提醒，主界面显示状态并提供授权入口。
- 当前主界面初始化时，若列表不含 `09:15`，会补入 `09:15` 与 `18:50`。
- 连接目标 WiFi 后打开飞书；未连接时通过前台服务等待，并提供「关闭监控」操作。
- 锁屏或后台启动受限时保留待打开状态及可点击的通知，解锁或点击通知后继续。待打开与 WiFi 等待状态支持恢复，仅在触发当天有效，避免第二天补执行前一天的提醒。
- 不自动收起滑动锁屏，也不请求锁屏全屏显示权限；正常使用时保持设备已解锁，意外锁屏时等待手动解锁后继续。
- 打开飞书前先显示不透明过渡页，获得焦点后等待约 1.5 秒，再切回飞书，处理飞书原本就在前台的情况。
- 定时触发、通知点击、解锁和「立即打开飞书」使用同一唤起流程。
- 定时触发及其通知/解锁续办在发出飞书启动请求约 5 秒后返回助手主界面。倒计时由前台服务持有，过渡页关闭不会取消；新一轮打开或提前手动返回助手会取消旧倒计时。手动「立即打开飞书」不自动返回。
- 自动流程在切回飞书前再次检查目标 WiFi；通知仅在真正发出飞书启动请求后清除。过渡页被 Home、锁屏或其他界面打断时取消延迟启动；WiFi 回调在等待结束后不再重复唤起。
- 橙色时钟图标、独立通知图标及 Android 13 主题图标。

## 设置周末自动打开

在主界面的监控时间列表上方开启「周末也自动打开」，再用右下角 `+` 设置提醒时间。开启后每天按这组时间执行；关闭后新的定时提醒仅在周一至周五触发。设置重启 App 后仍保留，已有的时间点不变。

周末仍需满足目标 WiFi 条件，锁屏时仍等待解锁。开关控制新的定时提醒；已经触发并进入等待 WiFi 或解锁的流程不因此取消。「立即打开飞书」按钮不受日期限制。

## 配置目标 WiFi

把以下配置添加到工程根目录的 `local.properties`，保留 Android Studio 自动生成的 `sdk.dir`：

```properties
target.wifi.ssid=你的办公WiFi名称
```

参考文件为 [`local.properties.example`](local.properties.example)。配置修改后需要重新构建安装。此文件按 UTF-8 读取，支持中文 WiFi 名称；反斜杠按 Java Properties 规则写作 `\\`。

`local.properties` 已被 Git 忽略，仓库中不保存你的实际 WiFi 名称。没有配置时，构建使用占位值 `YOUR_WIFI_SSID`。WiFi 名称会写入生成的 APK，分享 APK 时请使用适合公开的配置。

## 手机设置

根据系统提示授予通知、WiFi / 位置读取和后台位置权限，并开启系统定位服务。在系统设置中为「虾米爱打卡」允许后台运行、自启动及所需的悬浮窗权限，避免后台唤起被拦截。

Android 12 及以上请在主界面点击「授权闹钟和提醒」。悬浮窗权限和手机厂商的「后台弹出界面」权限用于切到助手过渡页及自动返回助手；前台服务负责 WiFi / 解锁等待和短暂的返回倒计时，并不自动获得后台启动页面的权限。如果系统仍拦截打开飞书，点击保留的打卡提醒可继续；若自动返回被拦截，点击常驻监控通知可返回助手。

系统闹钟可以在应用进程被回收或设备休眠后触发；被用户「强行停止」、权限撤销、厂商后台限制等情况仍会影响运行。强行停止或撤销闹钟权限后请重新打开助手并检查授权状态。

## 飞书一直停在前台时的处理

极速打卡要求在有效时段及考勤范围内激活客户端前台，而一直停在飞书页面不等于再次激活。参考 [Lark 官方极速打卡说明](https://www.larksuite.com/hc/zh-CN/articles/360048487794-%E8%AE%BE%E7%BD%AE%E6%9E%81%E9%80%9F%E6%89%93%E5%8D%A1)。助手只判断配置的 WiFi 名称，飞书仍会自行校验考勤 WiFi、位置、时段及账号条件。

每次定时打开飞书后自动返回助手；即使上次没有返回、飞书仍在前台，下次仍会先经过过渡页：

```text
系统闹钟触发 → 先安排下次闹钟 → 检查目标 WiFi
  ├─ 未连接：通知并等待 WiFi（当天有效）
  └─ 已连接：保存待办并发送提醒
       ├─ 锁屏：等待解锁
       └─ 未锁屏：打开不透明助手过渡页
            → 获得焦点后等待约 1.5 秒 → 再次检查 WiFi → 打开飞书
            → 约 5 秒后返回助手主界面，让飞书再次进入后台
```

如果后台弹出被拦截，待办和通知会保留，点击通知即可继续。无需在晚上手动退出或结束飞书进程。1.5 秒用于打开前的过渡，5 秒从发出飞书启动请求时开始计时，均不是飞书官方保证的打卡阈值。冷启动、定位或网络较慢时，5 秒可能不足以完成打卡；助手没有读取打卡结果。

自动返回时如果已锁屏、灭屏，或回调比预定返回时间晚超过 5 秒，则取消本次返回；不会在之后解锁时突然补执行。返回任务不跨进程恢复，服务被杀后可点击常驻通知或手动返回助手。自动返回会把助手主界面带到前台，包括你在这 5 秒内切到其他应用的情况；提前手动回到助手会取消旧返回任务。

## 真机验证

1. 连接目标 WiFi，将提醒设置为最近的工作日时间，让飞书保持前台。到点后应先显示过渡页，再打开飞书，约 5 秒后自动返回助手主界面。
2. 在飞书前台锁屏，等待提醒后解锁；通知点击也应经过过渡页。
3. 在过渡页等待期间按 Home 或锁屏，不应在等待结束后突然拉起飞书。
4. 从非目标 WiFi 切换到目标 WiFi，检查等待监控是否结束并进入唤起流程。
5. 以飞书显示的实际考勤结果为准；助手不读取打卡结果，前后台切换也不保证打卡成功。请在普通全屏模式下验证。
6. 周六或周日关闭「周末也自动打开」，设置一个尚未触发的未来时间，应不产生新的定时提醒；开启后用另一个未来时间验证正常触发，并重启 App 确认开关状态保留。周一至周五两种开关状态均应正常触发。
7. 设置两个未来时间，第一次自动返回助手后保持亮屏，第二次应再次经过过渡页、打开飞书并返回。再验证跨夜后的早上提醒，以及两次提醒之间手动打开飞书并停留的情况。
8. 检查「准时提醒」已授权，在系统回收助手进程后验证闹钟仍触发（不要用「强行停止」模拟普通进程回收）；重启手机后也应恢复后续时间点。
9. 关闭悬浮窗/后台弹出权限后保持飞书前台；若系统阻止自动切换，应留下通知，点击后可完成过渡。重新授权后再验证自动切换。
10. 在过渡页的等待期间切离目标 WiFi，应进入 WiFi 等待；等待完成后不应被旧网络回调反复拉起。未安装飞书时通知应保留且不应循环弹出过渡页。
11. 定时打开飞书后在 5 秒内锁屏，等待超过 5 秒再解锁，不应补执行返回。5 秒内手动返回助手后再打开其他应用，不应被旧倒计时拉回。点击「立即打开飞书」应保持飞书前台，不自动返回。

本地单元测试覆盖跨夜、工作日/周末、时间回拨去重、当前分钟恢复、跨年、无效时间、过期广播、时区/夏令时，以及 5 秒返回的单次消费、替换、取消和过期行为；后台弹出及实际极速打卡需要真机验证。

## 项目来源
「飞书」及包名 `com.ss.android.lark` 指本工具唤起的第三方客户端。本项目是独立辅助工具，与飞书官方无隶属关系。
